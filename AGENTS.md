# AGENTS.md — правила проекта jiraleaks

Правила для агентов, работающих в этом репозитории. Файл **специализирует** глобальные
правила из `~/.zcode/AGENTS.md` и не противоречит им: при конфликте побеждают глобальные,
а конфликт выносится пользователю.

## Что это за проект

`jiraleaks` — консольная утилита на Rust: сканирует Jira (задачи, комментарии, текстовые
вложения) на утёкшие секреты. Работает с Jira **только на чтение**. Пишет отчёты в шести
форматах, ведёт хранилище находок (SQLite/PostgreSQL) со сверкой статусов между сканами,
умеет отправлять алерты в Slack / Teams / вебхук.

## Стек и версии

- Rust, edition 2021, MSRV **1.97** (`rust-version` в `Cargo.toml`); toolchain ставится
  через mise, не через системный пакетный менеджер.
- Ключевые крейты: `tokio`, `reqwest` (rustls, без native-tls), `serde` / `serde_json` /
  `serde_yaml`, `clap` 4 + `clap_complete`, `fancy-regex`, `sha2`, `uuid`, `time`, `csv`,
  `url`, `tracing` + `tracing-subscriber`, `indicatif`, `sqlx` (Any: SQLite + PostgreSQL),
  `libsqlite3-sys` (bundled), `thiserror` / `anyhow`.
- Линты объявлены в `Cargo.toml`: `unsafe_code = "forbid"`, `clippy::all = "warn"`.
- Dev-зависимости: `wiremock` 0.6.
- Новую зависимость не добавлять без ADR и проверки CVE (`cargo audit`).

## Команды

Всё — через `justfile` (`just --list` показывает фактический список):

| Команда | Что делает |
| --- | --- |
| `just build` | `cargo build --release --locked` |
| `just test` | `cargo test --all-targets --locked` |
| `just lint` | `cargo clippy --all-targets --locked` |
| `just lint-strict` | То же с `-D warnings` — целевое состояние |
| `just fmt-check` | `cargo fmt --all -- --check` |
| `just fmt` | `cargo fmt --all` |
| `just docker-build` | Собрать образ `jiraleaks:dev` |
| `just docker-smoke` | Собрать образ и проверить точку входа (`--help`, `completions bash`) |
| `just docs-mermaid` | Отрендерить все Mermaid-блоки в отслеживаемых Markdown-файлах |
| `just scan` | Пример прогона с `--dry-run` (переопределяется `JIRA_URL`, `JQL`) |
| `just clean` | `cargo clean` |

`just docs-mermaid` требует `mmdc` (mise: `mise use -g npm:mermaid-cli`). Любая новая
диаграмма обязана пройти эту проверку до коммита.

Минимальный набор перед коммитом: `just fmt-check && just lint && just test`. Цель — чтобы
`just lint-strict` был зелёным.

## Тесты

- Unit-тесты живут рядом с кодом (`#[cfg(test)] mod tests`), интеграционные — в `tests/`.
- Jira мокается через `wiremock` (`tests/integration.rs`, `tests/attachments.rs`,
  `tests/alert_payloads.rs`); реальная сеть в тестах недопустима.
- Хранилище тестируется на `sqlite::memory:` — у каждой коннекции в пуле **своя** база,
  поэтому тесту нужен один коннект, а не пул.
- Новый функционал и каждый багфикс обязаны нести тесты, включая граничные случаи и пути
  ошибок, а не только happy path.
- Золотые тесты детекции (`tests/rules_detection.rs`, `tests/detection_quality.rs`)
  фиксируют покрытие правил: менять их только осознанно и объяснять причину в коммите.
- `tests/snippet_redaction.rs` — инвариант маскирования, `tests/hostile_input.rs` — потолки
  стоимости и нейтрализация вывода, `tests/config_cli.rs` — контракт CLI и дефолтов (список
  дефолтов в нём переписан по таблице README вручную: меняя дефолт, правь оба места),
  `tests/report_formats.rs` — каталог форматов и защита `report_dir`, `tests/identity.rs` —
  три идентичности находки, `tests/allowlist.rs` — контракт `field` и строгая загрузка.
- Тест, который «падает иногда» или обходит проверку, считается сломанным: сначала фикс,
  потом коммит.

## Дисциплина безопасности

Инварианты, которые нельзя нарушать ни при каких обстоятельствах:

1. **Сырой секрет не попадает никуда** — ни в отчёт, ни в БД, ни в лог, ни в алерт. Только
   маскированный превью, хеш `sha256:` и сниппет, в котором замаскированы и сам секрет, и
   соседние секреты того же окна. Новый формат отчёта, новый канал алертов или новое поле
   обязаны нести тест на отсутствие сырого значения.
2. **Текст из Jira — граница недоверия**: описания, комментарии, имена вложений, пути полей,
   `content`-URL вложений. Любой такой текст, попадающий в отчёт, лог или терминал, проходит
   `sanitize::terminal` или `sanitize::csv_field`. Никакой интерполяции недоверенного текста в
   shell или SQL.
3. **Любая сетевая загрузка** обязана: проверять origin (та же схема, хост и эффективный
   порт — сравнение origin, не префикса), иметь лимит по размеру (стриминг с обрывом на
   лимите) и по количеству, и при ошибке писать предупреждение со счётчиком, а не ронять
   задачу или скан.
4. **Любой цикл по враждебному тексту имеет потолок стоимости** (байты, число совпадений,
   число находок) и тест с враждебным входом, проверяющий и результат, и время.
5. **Конфиги загружаются строго**: неизвестный ключ, пустое значение предиката, непригодная
   запись — ошибка конфигурации с кодом выхода 1, а не молчаливый дефолт.
6. **Токен Jira и URL вебхуков — bearer-секреты**: не логируются, маскируются в `Debug`, не
   попадают в текст ошибок.
7. Секреты и артефакты сканов не коммитить: `reports/`, `.jiraleaks-state/`, `*.db` уже
   перечислены в `.gitignore` и `.dockerignore`.

## Процесс

- Conventional commits: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`, `ci:`,
  `perf:`. Один коммит — одно связное изменение с зелёными тестами.
- Каждое изменение поведения отражается в `CHANGELOG.md` (секция `Unreleased`, подсекции
  Added / Changed / Fixed / Removed / Security). Версии не выдумывать.
- Значимое или неочевидное решение (крейт, формат отчёта, схема БД, схема аутентификации,
  новая сетевая интеграция) → ADR в `docs/adr/NNNN-short-title.md`. Записанное решение не
  редактируется: изменённое оформляется новым ADR со ссылкой «Superseded by NNNN».
- Изменение состава компонентов или потоков данных → `ARCHITECTURE.md` правится в том же
  коммите.
- `README.md` и `README.ru.md` обязаны совпадать по фактам между собой и с кодом. Если
  README расходится с `--help` или кодом — прав код, README правится тем же коммитом.
- Все диаграммы — Mermaid в Markdown-блоках, проверенные `just docs-mermaid`. ASCII-графики
  и картинки не использовать.

## CI

- `.github/workflows/ci.yml` — обязательная проверка: `rustfmt --check`, `clippy`, `cargo
  test --all-targets`, сборка Docker-образа и smoke-тест точки входа. Красный CI — блокер,
  а не «починим потом». Локальный аналог: `just fmt-check && just lint && just test`.
- Пуш только по явной просьбе пользователя; работа ведётся в ветке, не в `master`.

## Бюджет агентов

- Не более **4** субагентов одновременно в этом проекте.
- Параллельно запускаются только задачи с непересекающимися скоупами файлов; общий файл —
  только последовательно. Агент не порождает других агентов.
