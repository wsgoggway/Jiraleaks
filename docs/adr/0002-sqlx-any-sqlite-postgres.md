# 0002. Два диалекта SQL через sqlx `Any` и одну точку ветвления

- Статус: принято
- Дата: 2026-09-24

## Контекст

Хранилище находок ведёт историю статусов между сканами: закрытие исчезнувших находок,
`first_seen`, `times_seen`, аудит прогонов и соединение с внешними live-валидациями.
Локально (ноутбук инженера, изолированный тест, CI) нужен файл без сервера; в промышленной
эксплуатации нужен сервер БД, к которому ходят несколько сканеров. Поведение обязано
совпадать: тесты на файле не должны ничего говорить о другом поведении в проде.

## Решение

Один код и один SQL на оба диалекта через `sqlx::Any`. Единственное место, знающее про
различия, — `FindingsStore::ph(i)`: SQLite получает `?`, PostgreSQL `$n`. Схема описана
переносимым идемпотентным DDL (`CREATE TABLE IF NOT EXISTS`), миграция применяется
построчно (SQLite выполняет один оператор на подготовку), а upsert использует переносимый
`ON CONFLICT (...) DO UPDATE SET ... EXCLUDED`.

## Альтернативы

- **Только SQLite.** Проще всего, но исключает серверную БД: несколько сканеров не смогут
  смотреть в одно хранилище, а операционные требования (бэкапы, реплики, права) не покрыть.
- **ORM (diesel, sea-orm).** Типизированные запросы и миграции «из коробки», но генерация
  под два диалекта сложнее, чем пара плейсхолдеров, а слой абстракции закрывает то, что
  здесь как раз важно — точный текст запроса в reconcile.
- **Два крейта или два модуля, по одному на диалект.** Двойная реализация реконсиляции —
  это двойная логика закрытия находок, и расхождение между локальным и промышленным
  поведением стало бы вопросом времени, а не вероятности.
- **Свой тонкий слой над обоими драйверами.** То же, что `Any`, но написанное и
  поддерживаемое вручную.

## Последствия

- Один путь кода и одна реализация `reconcile`; тесты выполняются на SQLite в памяти
  (`sqlite::memory:`), прод работает на PostgreSQL.
- `ph()` — обязательная дисциплина при каждом новом запросе: интерполируются только номера
  заполнителей, значения всегда идут через `.bind()`, поэтому инъекция невозможна по
  построению, но обойти `ph()` и написать `$1` руками всё же можно — это проверяется
  ревью, а не компилятором.
- `Any` стирает типы: `BOOLEAN` читается как целое (`CAST(valid AS INTEGER)`), поэтому
  преобразования сосредоточены в `store.rs` и покрыты тестами.
- Возможности, специфичные для одного диалекта (JSONB, `RETURNING`, частичные индексы,
  оконные функции), недоступны, пока их не поддержат оба; при необходимости такой запрос
  придётся выносить в ветку, и это будет второе место с диалект-спецификой.
- Схема и её применение живут в одном файле `migrations/0001_init.sql`, который встроен в
  бинарник через `include_str!`, поэтому миграция не может «потеряться» при деплое.
